Transformer#

Sometimes the most convenient Python-facing representation of a value isn’t the same as its representation on the wire. A percentage might be stored as a single scaled byte, or a MAC address as six raw bytes instead of a colon-separated string. Rather than writing a brand-new struct class from scratch every time this happens, wrap an existing one with Transformer and only describe the translation between the two representations.

Several built-in structs are themselves just Transformer subclasses: Const (enforces a constant value), Enum (maps between raw values and Python enum members), ZLibCompressed and derivates (compress/decompress a nested struct), and MACAddress (formats six raw bytes as a colon-separated string).

A basic example#

Suppose a byte should be exposed as a floating-point ratio between 0.0 and 1.0 instead of a raw 0-255 integer. Subclass Transformer, wrap the underlying uint8 field, and override encode() and decode():

A custom Transformer scaling a byte to a ratio#
# generic typing parameters read as [IN, IN_TRANSFORMED, OUT, OUT_TRANSFORMED]
class Percentage(Transformer[float, int, float, int]):
    def __init__(self) -> None:
        super().__init__(uint8)

    def encode(self, obj: float, context) -> int:
        return round(obj * 255)

    def decode(self, parsed: int, context) -> float:
        return parsed / 255

@struct
class Progress:
    percent: Percentage()

@struct
class Progress:
    percent: f[float, Percentage()]

Unpacking calls the wrapped uint8 field first, then decode on its result; packing does the reverse, calling encode first and feeding its result to the wrapped field’s __pack__:

>>> unpack(Progress, b"\x80")
Progress(percent=0.5019607843137255)
>>> pack(Progress(percent=0.5))
b'\x80'

Typing#

Transformer is generic over four type parameters, describing the two representations on either side of the translation:

class Transformer(Generic[_IT, _IT_transformed, _OT, _OT_transformed], FieldStruct[_IT, _OT]):
    ...

  • _IT - the type accepted from user code when packing (the argument to encode).

  • _IT_transformed - the type produced by encode, i.e. what the wrapped struct expects to pack.

  • _OT_transformed - the type produced by the wrapped struct when unpacking, i.e. the argument to decode.

  • _OT - the type produced by decode, i.e. the type user code ultimately sees.

For Percentage above, both directions share the same pair of types - float on the Python side, int on the wire - so it is declared as Transformer[float, int, float, int].

For the full API, see Transformer in the library reference.
